# Authoring

This example changes JSON on `POST https://api.example.com/search` before forwarding a request or response.

## Tools

Linux and macOS use the same commands. Install Bun %%BUN_VERSION%%, Python 3, OpenSSL, Git, Rust and a C compiler, or use the [dev container](devcontainer.md). Creating, testing and signing plugins does not require Xcode.

## Files

Use `src/NAME.ts` for source, `manifests/NAME.json` for identity, conditions and grants, and `fixtures/cases.json` for tests. Source and manifest share a lowercase kebab-case basename. Generate a plugin UUID once and retain it after publication:

```sh
python3 -c 'import uuid; print(uuid.uuid4())'
```

## Edit JSON {#edit-json}

The first argument to `Interceptor.attach` selects the target. The callback does not need to repeat host or method checks.

```ts
const search: Interceptor.Match = {
  hosts: ['api.example.com'],
  methods: ['POST'],
  path: { kind: 'exact', value: '/search' }
};

Interceptor.attach(search, {
  request: {
    onEnter(req, cfg) {
      if (!req.body || typeof req.body !== 'object' || Array.isArray(req.body)) return;
      req.body.limit = 5;
    }
  },
  response: {
    onEnter(res, cfg) {
      if (!res.body || typeof res.body !== 'object' || Array.isArray(res.body)) return;
      res.body.maintenance = true;
    }
  }
});
```

`req` is the request, `res` is the response, and `cfg` is plugin configuration. This example does not use `cfg`; you can omit the second parameter when configuration is unnecessary.

These callbacks change fields only when the body is a JSON object. Missing bodies and arrays remain unchanged. `attach` already checks the host and method, so callbacks need no repeated target guards.

The manifest declares the same target and permission to read and write JSON:

<<< ../../manifests/request-summary.json{json}

A request body changes from:

```json
{"query":"x","limit":50}
```

to:

```json
{"query":"x","limit":5}
```

A response body changes from:

```json
{"ok":true}
```

to:

```json
{"ok":true,"maintenance":true}
```

`body` is parsed JSON. Assign fields or work with arrays directly, according to your API's input shape. Use `request.onLeave` and `response.onLeave` for processing after successful local forwarding. See [the four callbacks](api.md#request-onenter).

## Test cases

Add input and expected output in `fixtures/cases.json`. V2 uses `phase` with one of the four hook names:

```json
{
  "name": "search limit changed to five on enter",
  "plugin": "request-summary",
  "phase": "request.onEnter",
  "event": {
    "phase": "request.onEnter",
    "request": {
      "method":"POST", "host":"api.example.com", "path":"/search",
      "body":{"query":"x","limit":50}
    }
  },
  "expected": {"actions":[], "mutation":{"body":{"query":"x","limit":5}}}
}
```

The runtime produces `mutation`; callback authors only edit `body`. Use `expectError: "scriptError"` instead of `expected` to test failure. Cover unmatched traffic and forbidden edits in a leave callback.

## Build and validate

```sh
bun install --frozen-lockfile --ignore-scripts
bun run check:authoring
bun run check
bun run build
```

`check:authoring` runs type checks, tests and package generation; `check` also covers signatures and tamper detection. `build` creates unsigned development packages in `build/site/`, which must be absent or empty. Remove only previous generated output before retrying.

`build/scripts/` is regenerated from TypeScript. Do not edit or commit generated JavaScript. Increment the manifest version when source or generated bytes change.

## Rust simulator

`interceptor-simulator` uses the app's QuickJS bridge for syntax and execution checks. Its first build fetches pinned source and requires Rust and a C compiler.

```sh
bun run simulator check build/scripts/request-summary.js
bun run simulator run build/scripts/request-summary.js request.onEnter fixtures/request-event.json fixtures/config.json --manifest manifests/request-summary.json
```

Both input files are included in this repository. `fixtures/request-event.json` supplies traffic data, while `fixtures/config.json` supplies the callback's second argument:

Copy and edit them for your API. `fixtures/cases.json` also contains expectations and cannot be passed directly to `run`.

`check` compiles without executing. `run` executes one phase and validates matching, grants and edits. Running a schema 2 plugin requires `--manifest`. It does not forward traffic or deliver webhooks. Verify actual network ordering in the app.

After building, run `.tools/bin/interceptor-simulator` directly. A binary for the same OS/CPU does not require Bun, Python, Rust or Xcode at runtime. Linux still requires compatible system libraries.

## Publish

Packages use Ed25519 signing. Register the key with [Publishing](publishing.md); CI signs and distributes on pushes to master.
