# はじめに

スキーマ2と実通信のHookに対応するInterceptorの配布は準備中です。公開時にバージョンと入手先を案内します。現在はLinuxまたはmacOSで、[作成ガイド](authoring.md)のRustシミュレーターによる合成テストを利用できます。

以下のアプリ操作は対応版の公開後の手順です。プラグインは読み込んだだけでは実通信に適用されません。無効状態のまま合成テストし、実通信で使うリビジョンを別途承認します。

## リポジトリを追加する

リポジトリを追加すると、配布されているプラグインの一覧が表示されます。リポジトリを追加しただけではスクリプトは実行されません。一覧からスクリプトを選び、無効な状態で読み込んでテストします。

**設定 → Plugins → ＋ → リポジトリを追加**を開き、次のURLを入力します。

```text
%%REPOSITORY_URL%%
```

追加前のプレビュー画面ではリポジトリ名とスクリプト数を確認できます。署名付きの場合は、署名鍵のフィンガープリントも表示されます。すべてのソースファイルと、対象条件や権限などを定義したmanifestは、リポジトリの追加後に各スクリプトの詳細画面で確認します。

## 信頼の確認

フィンガープリントは配布元の署名鍵を識別する64文字の値です。次の手順で、Interceptorに表示された鍵が、信頼している配布元のものかを確認します。

このリポジトリの公開鍵（Ed25519）のSHA-256フィンガープリント:

```text
%%FINGERPRINT%%
```

1. Interceptorのリポジトリ追加プレビューに表示されたフィンガープリントを確認します。
2. 以前から信頼している配布元の連絡先など、このサイト・フィードとは別の経路で比較用のフィンガープリントを入手します。
3. 2つの値が**64文字すべて一致するか**確認します。比較用のフィンガープリントを入手できない場合や、値が一致しない場合、有効なフィンガープリントが表示されない場合は、その鍵が信頼している配布元のものだと確認できません。信頼せず、追加を中止してください。

このページの値だけでは確認は完了しません。このサイトとフィードは同じGitHub管理権限の下にあり、独立した確認経路ではありません。このページでは別経路の確認先を案内していません。

- **パッケージのSHA-256**は一覧とパッケージの不一致を検知するものです。署名のない配信元では両方を差し替えられます。
- **公開鍵のフィンガープリント**は署名鍵を識別するSHA-256値です。初めて見る鍵の署名が正しくても、公開者の本人確認にはなりません。
- **Ed25519署名**は、一覧とそこに記載されたパッケージのハッシュが、その鍵で署名されてから変わっていないことを確かめます。

## 読み込んでテストする

合成テストでは実際の通信を送らず、指定したJSONに対する実行結果を確認できます。Webhookも送信しません。

1. 一覧からパッケージを選び、すべてのソースファイルとmanifestを確認します。
2. 無効な状態で読み込みます。
3. スクリプトの詳細を開き、試すHookを選びます。HTTP本文だけでなくホストなどの通信情報も含むJSONを入力し、合成テストを実行します。

<<< ../fixtures/request-event.json{json}

結果の本文プレビューに`{"query":"x","limit":5}`が表示されれば、想定した書き換えを確認できます。ホストを`other.example.com`へ変えた場合は、条件に一致せず変更されません。

合成テストは1回につき1つのHookを実行します。`request.onLeave`を選んでも実際にリクエストを送るわけではありません。転送後に渡される内容を入力として用意して試します。

ソースコードを変更する場合は、開発環境の`plugins/NAME/hooks/`を編集し、`bun run build`で再ビルドして、生成されたパッケージを読み込み直します。

## 実通信で使う

対応版の公開後、スキーマ2のスクリプトで次の順に操作します。`api.example.com`は説明用のホストです。実通信を試す場合は、自分が利用するAPIを対象にしたプラグインを用意してください。

<HookFlow locale="ja" />

1. **設定 → キャプチャ設定**を開き、画面の案内に従って証明書とVPN構成を設定します。証明書を信頼すると、選択したホストのHTTPS通信をInterceptorが復号できるようになります。
2. **設定 → プロキシ対象リスト**を開き、試すホストを追加します。スクリプトの対象条件に表示されたホストです。
3. **設定 → Plugins**でスクリプトの詳細を開き、対象条件・ソース・読み書きの権限を確認します。**実通信での使用 → 実通信での使用を承認…** を選び、確認画面で**OK**を押します。ここでのリビジョンは表示されている全ソースファイルとmanifestをまとめたパッケージです。
4. **設定**に戻って**接続状態**をオンにし、対象の通信を発生させます。**ホーム**に表示された対象ホストの通信を開き、送信したJSONや返されたJSONを確認します。

承認すると、指定した通信の情報をスクリプトが読み取れます。本文の変更を許可した場合は、サーバーへ送るJSONやクライアントへ返すJSONが変更されます。

承認の追加や取り消し、スキーマ2のスクリプトの削除で、現在のキャプチャ接続を終了します。変更は、次に利用者が接続したときから適用します。プラグインの承認だけでは、復号対象のホストは追加されません。

読み込みだけでは有効になりません。内容を変更した版や更新版は、改めて確認して承認します。不要になったら承認を取り消すかスクリプトを削除してください。承認の取り消しで、実行中の接続も終了します。

実通信で使えるのはJSON本文を扱う4つのHookです。対象の本文サイズや通信形式には[制限](api.md#実行条件と制限)があります。Webhookへの外部送信と、ショートカットからの任意実行には対応していません。
